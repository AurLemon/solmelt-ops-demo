# 任务书验收基线

## 项目本质

本项目不是复刻真实电站系统，也不是展示 AI 生成页面；它是一个可现场运行的教学版闭环：模拟泵数据被接收、保存、判定报警、查询并在大屏展示。老师考核功能完整性、数据闭环、方案书质量和成员对 AI 协作及代码的真实理解。

## 权威来源

1. `.requirements/复现任务.docx`：任务、评分、四板块最低要求。
2. `.requirements/学生复现-物模型/` 内 9 份 JSON：产品标识、9 台设备、30 个属性的唯一事实源。
3. `.requirements/学生复现-参考截图/`：页面信息密度与工业场景参考。
4. `.requirements/熔盐泵原理入门.html`：领域解释与可选加分灵感。
5. `.team/1. 项目方案书.md`：本组已冻结的协作和技术方案。

发生冲突时必须按上述顺序处理，不得让 AI 自行猜测字段、设备或业务规则。

## 四组最低验收

| 领域      | 必须交付                                                                                             |
| --------- | ---------------------------------------------------------------------------------------------------- |
| Auth      | 图形验证码、管理员与普通用户登录、JWT、路由守卫、用户/角色/菜单管理、前后端双重权限拦截              |
| Device    | 立式熔盐泵产品、30 个物模型属性、9 台真实编号设备、设备编辑/逻辑删除/启停、最新值与五分钟在线判定    |
| Telemetry | HTTP 上报、启用设备校验、按设备+时间+属性持久化、65℃/4.5 mm/s/60 A 三项报警、Python 模拟器、历史曲线 |
| Dashboard | 1920×1080 暗色自适应大屏、至少六张统计卡、实时状态、近期报警、30 秒轮询、数据延迟标识                |

## 答辩灵魂链

管理员与普通用户登录并展示权限差异 → 启动模拟器 → 9 台设备出现在线状态 → 异常数据产生报警并同步到大屏 → 查询历史曲线 → 停止模拟器 → 页面保留最后真实值并显示延迟。

答辩前必须完整彩排至少一次；每位成员都要能说明自己领域的数据流、接口和 AI Review 结果。

## 非必做与加分项

健康评分、五路振动合成判据、复杂运行模式、MQTT、消息队列、完整报警状态机和像素级截图复刻均非最低验收。未得到组长明确批准前不得占用最低验收时间。
