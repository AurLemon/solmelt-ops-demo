# UI 规范

本规范约束 SolMelt 的后台管理页、监测大屏和登录页。目标不是像素级复刻参考系统，而是让四个 Layer 在合并后形成一致、可读、可操作的工业管理界面。

## 设计基线

- 产品气质：安静、克制、信息密度适中，优先支持扫描、比较和重复操作，不做营销页式大标题、装饰性渐变或无业务意义的卡片堆叠。
- 技术基线：优先使用 Nuxt UI 与 Tailwind CSS；图标使用已安装的 Lucide 集合。ECharts 只负责图表，不重复实现表单、按钮或弹窗。
- 主题：首次访问默认暗色；用户手动切换后沿用 Nuxt Color Mode 的持久化结果。浅色与暗色是同等支持的状态，不允许只在全局 CSS 中事后补救不可读组件。
- 色彩：中性灰用于结构，琥珀色用于品牌和主要强调，绿色表示正常/成功，红色表示错误/危险，黄色表示警告。不要用单一色系覆盖整个页面。

全局无衬线字体使用 Rubik，由根 `nuxt.config.ts` 的 Head 通过 Google Fonts CDN 加载（`display=swap`），`app/assets/css/main.css` 统一设置 `--font-sans`。中文回退系统无衬线字体，等宽字体保持原有配置。Rubik 在 Nuxt Fonts 中设置 `provider: 'none'`，避免构建时再次下载或改用其他字体源。Layer 不单独配置字体或字体 CDN。

## 页面结构

- 后台业务页统一使用 `dashboard` Layout，并在 `definePageMeta` 声明页面读取权限；大屏可以使用专用全屏结构，但仍复用主题与鉴权边界。
- 页面标题通常使用 `text-xl` 或 `text-2xl`，附属说明使用 `text-sm`。只有登录页或真正的全屏展示可使用更大的展示文字。
- 页面主体以 `space-y-4` 或 `space-y-5` 组织；筛选、统计、表格和分页是连续区域，不把每个小段都包装为漂浮卡片，也不嵌套装饰性卡片。
- 业务面板圆角不超过 `rounded-lg`，紧凑控件优先 `rounded-md`。表格、工具栏和固定格式网格应设置稳定宽度、列宽或最小高度，避免加载和动态内容导致布局跳动。

## 组件与操作

- 命令使用 `UButton`；有明确通用图标的按钮使用 Lucide 图标，纯图标按钮必须提供 `aria-label` 或 `title`。不要用带文字的圆角矩形代替常见的编辑、删除、播放、暂停、返回等图标操作。
- 文本、选择、复选、模态框、提示和徽标分别使用 `UInput`、`USelect`、`UCheckbox`、`UModal`、`UAlert`、`UBadge`。只有文件上传等 Nuxt UI 没有合适封装的原生控件可以保留，并须匹配两种主题。
- 新增、编辑放入表单或 Modal；危险操作必须二次确认并清楚说明影响。提交期间禁用重复操作，完成后显示成功反馈并刷新真实数据。
- 二元设置使用开关或复选框；有限选项使用 Select 或分段控制；数值使用合适的数字输入。不要用自由文本承载明确枚举。
- 只读角色不得只靠隐藏按钮保护，服务端仍必须校验权限；界面按权限隐藏不可执行的写操作。

## 数据状态与反馈

每个异步页面必须覆盖以下状态：

| 状态       | 最低表现                                               |
| ---------- | ------------------------------------------------------ |
| loading    | 稳定高度的加载区和旋转图标，不清空为白屏               |
| empty      | 说明当前没有数据，并在有权限时提供明确的下一步操作     |
| error      | 使用 `UAlert` 显示可公开的具体错误，不只记录到控制台   |
| ready      | 展示真实数据、数据时间和必要单位，不用占位业务数组     |
| delayed    | 保留最后真实值并单独标记延迟，不把延迟误写成故障或零值 |
| submitting | 禁止重复提交；成功或失败后给出可见反馈                 |

- 服务端 `ApiFailure.message` 应在不泄露敏感信息的前提下传到页面；验证码刷新、重新请求或关闭 Modal 不得无意清除仍需用户看到的错误。
- 表格数字和设备编号使用 `font-mono`、`tabular-nums`；时间按北京时间显示，接口仍传 UTC ISO 8601。
- 在线、启用、报警状态必须使用既有业务语义和统一标签，不根据颜色或单个数值自行创造状态。

## 主题、图表与动效

- 新增 Tailwind 色彩类时成对检查浅色和 `dark:` 状态。文字与背景必须保持可读对比度；禁用态不能与可点击态难以区分。
- ECharts 的背景、坐标轴、图例、Tooltip 和文字颜色必须随当前主题更新；主题切换后要触发图表重绘或更新配置。
- 动效限定在侧栏、Modal、主题切换、加载和轻量 hover 反馈，常规时长控制在 150-360 ms。不得让持续动画干扰实时数据读取。
- 所有自定义动效必须为 `prefers-reduced-motion: reduce` 提供无动画路径。

## 响应式与可达性

- 桌面端侧栏保持稳定，主内容允许滚动；移动端使用抽屉或遮罩式导航，关闭后焦点和页面状态不得丢失。
- 表格在窄屏允许横向滚动，不压缩到文字互相遮挡；工具栏可换行，按钮文字不得溢出。
- 表单控件必须有关联标签；图标按钮必须有可访问名称；状态不能只靠颜色表达。
- 页面必须支持从侧栏客户端导航进入，也必须支持刷新和直接 URL 访问。至少验证桌面与移动端各一个视口。

## 提交前 UI 核验

1. 从正式登录开始，通过左侧菜单进入修改页面，不直接输入目标 URL。
2. 检查客户端跳转、刷新、浏览器前进/后退，以及权限不足时的跳转或提示。
3. 分别检查暗色和浅色的标题、正文、边框、表格、Modal、Tooltip 和图表。
4. 人工触发 loading、empty、error、ready；涉及写操作时再检查 submitting、成功和失败反馈。
5. 检查一个桌面视口和一个移动视口，无重叠、截断、白屏或布局跳动。
6. 执行 `pnpm pr:check` 和 `git diff --check`；Build 通过后仍须报告上述人工路径的实际结果。
