# 登录与权限领域

## 允许范围

本领域实现默认写入 `layers/auth/**`，固定分支为 `feat/auth`；Agent 可以阅读全仓库追踪数据流，但不得修改公共契约、Schema、migration、依赖、根配置或其他 Layer。上述公共面由组长维护。

## 必须实现

- 图形验证码：四位、五分钟过期、使用后失效。
- JWT 登录：管理员和普通操作员两种角色。
- 用户、角色和菜单管理；用户删除采用逻辑删除。
- 未登录访问系统页面跳转登录；无权限访问页面与 API 均被拒绝。
- 前端菜单隐藏不能替代服务端权限校验。

## 不可变规则

- 使用 `shared/contracts/auth.ts` 中的 Claims、角色码和权限码。
- `ADMIN`、`OPERATOR` 是 Seed 的内置角色；角色管理允许新增角色，鉴权必须以权限码而非两种角色白名单为准。
- 密码只保存 bcrypt hash，不得返回密码或 hash。
- API 使用 `/api/v1/auth/*`，响应必须使用统一 `ApiResult<T>`。
- 只操作 auth 领域表，成功后可发布事件，不得调用其他领域 Service。
- 不得硬编码临时用户数组或绕过数据库。

## 验收

管理员与普通操作员均可登录；菜单和接口权限存在明显差异；验证码错误、过期和重复使用均失败；直接输入无权地址会被前后端共同拦截。
