# 数据采集、查询与报警领域

## 允许范围

本领域实现默认写入 `layers/telemetry/**` 和 `scripts/simulator/**`，固定分支为 `feat/telemetry`；Agent 可以阅读全仓库追踪数据流，但不得修改公共契约、Schema、migration、依赖、根配置或其他 Layer。模拟器目录是本领域的明确例外，上述其他公共面由组长维护。

## 必须实现

- HTTP 数据上报接口与 Zod 校验。
- 上报、属性值、最新值和报警持久化。
- 历史曲线查询与多设备对比。
- Python 随机游走模拟器，10 至 30 秒发送一次，偶发注入明确标注的异常值。
- 报警查询；完整报警状态处理属于可选项，需在最低数据闭环完成后经组长批准。

## 不可变规则

- API 使用 `/api/v1/telemetry/*`，输入遵循 `TelemetryReportInput`。
- 只接受存在且已启用设备的数据；30 个属性必须来自物模型定义。
- 驱动端轴承温度、泵振动 X、变频器电流阈值固定为 65、4.5、60。
- 核心上报提交成功后发布 `telemetry.reported`；最新值和报警通过事件处理。
- 模拟器数据是任务要求的数据源，不是页面 Mock；不得在页面或接口里塞静态假数组，也不得擅自扩展 MQTT、消息队列或复杂五路振动判据。
- 不得调用设备或大屏领域 Service。

## 验收

模拟器可持续上报；正常数据形成历史曲线；异常值生成报警；停用设备被拒收；大屏能够消费最新值和报警。
